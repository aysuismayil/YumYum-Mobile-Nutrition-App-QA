Reusable template for filing bug reports in this project. Copy this structure for each new bug.

## Title
_Concise title describing the observable problem_

## What Happens
_Description of the actual behavior observed_

## Preconditions
_State needed before reproducing, when applicable. Use "N/A" if none._

## Steps to Reproduce
_Numbered, reproducible steps (1., 2., 3., ...)_

## Expected Instead
_What should happen instead_

## Area
_e.g. Challenge, Profile, Notifications_

## Severity
_Use "Not confirmed" if not yet established_

## Priority
_Tracked separately from Severity. Use "Not confirmed" if not yet established_

## How Often / Repro Rate

## Workaround

## App Version and Build
_Version / build number, or "Not confirmed"_

## Device and iOS Version
_Device model and iOS version_

## Account State
_Relevant account state at time of reproduction_

## Device Language
_Device language setting_

## Evidence
_Screenshots or screen recordings_

## First Seen In
_Version/build first observed. Leave blank if not established_

---

## Rules for Use

- One bug per issue.
- Titles must be concise and describe the observable problem.
- Steps must be numbered and reproducible.
- Do not speculate about root cause.
- Do not invent missing information — use "Not confirmed" or "N/A" when appropriate.
- Priority and Severity must remain separate.
- Evidence can include screenshots or screen recordings.
- First Seen In should remain blank/unknown if it was not actually established.
